# ESP32 Home Dashboard — десктоп приложение

Малко Electron приложение, което седи в system tray (до часовника) и
показва gauge-и с текущите данни от ESP32 сензора, без да пречи на
работния плот. Виж основния план на сесията за пълна история на
дизайна.

## Разработка (dev режим)

```powershell
cd desktop
npm install
npm start
```

Това пуска приложението директно от изходния код — удобно за тест на
промени, но изисква Node/Electron да са налични и не е нещо, което
можеш да инсталираш на друг компютър.

## Компилиране на .exe инсталатор

```powershell
npm run dist
```

Резултатът е в `desktop/dist/`:
- `ESP32 Home Dashboard Setup <версия>.exe` — самият инсталатор
  (NSIS, per-user, без нужда от admin права, стартира приложението
  автоматично след инсталация).
- `latest.yml` — метаданни, ползвани от auto-update механизма.

`desktop/dist/` **не** се качва в git (виж `.gitignore`) — генерира се
локално всеки път, когато е нужно.

## Auto-update (публикуване на нова версия)

Инсталираното приложение проверява GitHub Releases на това repo (при
стартиране и после на всеки 6 часа) за нова версия, сваля я тихо във
фонов режим, и показва известие + бутон "Restart to install update" в
tray менюто, когато е готова. За това да проработи, трябва **ти** да
публикуваш нова версия като GitHub Release всеки път, когато искаш да
разпространиш ъпдейт. Стъпки:

### 1. Създай GitHub Personal Access Token (само веднъж)

1. Отвори https://github.com/settings/tokens?type=beta (Fine-grained
   tokens) или https://github.com/settings/tokens (classic — по-лесно
   за начало).
2. Ако ползваш **classic** token: "Generate new token (classic)" →
   дай му име (напр. `esp32-dashboard-release`) → сложи отметка на
   scope **`repo`** (пълен достъп до частни/публични repo-та за
   releases) → Generate token.
3. Копирай токена веднага (показва се само веднъж!). Пази го като
   парола — не го качвай в git, не го споделяй.

### 2. Задай токена като environment variable

Във всеки нов PowerShell прозорец, преди `npm run release`:

```powershell
$env:GH_TOKEN = "<твоя_токен_тук>"
```

(Важи само за текущия прозорец — трябва да го пишеш всеки път, освен
ако не го запазиш трайно през Windows System Properties → Environment
Variables, което е по-удобно ако ще пускаш release-и често.)

### 3. Бъмни версията и публикувай

Преди всеки release, увеличи `"version"` в `desktop/package.json`
(напр. `1.0.0` → `1.0.1`), после:

```powershell
cd desktop
npm run release
```

Това компилира инсталатора **и** го качва като GitHub Release,
заедно с `latest.yml`. Всички вече инсталирани копия на приложението
ще открият новата версия при следващата си проверка (до 6 часа, или
веднага при рестарт на приложението).

### Забележка

Ако не зададеш `GH_TOKEN`, `npm run release` ще гръмне с грешка при
опит за качване. `npm run dist` (без `--publish`) винаги работи
локално, без токен — просто няма да публикува нищо.
